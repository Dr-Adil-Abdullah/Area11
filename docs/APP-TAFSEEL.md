## 1. ایپ کیسے چلتی ہے (ایک نظر میں)

- یہ ایک **Next.js + SQLite** ایپ ہے جو **دکان کے کمپیوٹر** پر چلتی ہے۔
- **انٹرنیٹ کے بغیر بھی پوری چلتی ہے** (سوائے کلاؤڈ سنک اور WhatsApp لنک کے)۔
- ڈیٹا ایک ہی فائل میں ہے: `data/area11.db` (تصویریں `data/photos/` فولڈر میں)۔
- **Node.js ≥ 22.5** درکار ہے (SQLite بلٹ اِن ہے) — کوئی اور ڈیٹا بیس انسٹال نہیں کرنا۔
- دکان کے دوسرے آلات (ٹیب/فون) اسی وائی فائی پر `http://<پی سی کا IP>:3000` کھول سکتے ہیں۔

**چلانے کا طریقہ**

```
npm install
npm run dev      # ٹیسٹ کے لیے (http://localhost:3000)
npm run build && npm start   # دکان میں استعمال کے لیے
```

## 2. بنے ہوئے فیچرز (صفحہ بہ صفحہ)

### 2.1 Counter / Billing — `/pos`
- Box / Strip / Tablet میں بیچنا — پیک کا فارمولا آپ خود رکھتے ہیں (1 بکس = کتنی پٹی، 1 پٹی = کتنی گولی)۔
- **FEFO**: جو بیچ جلدی ختم ہو رہا ہو وہ پہلے بکتا ہے (منہگی/خراب ہونے والی دوائی کا نقصان کم)۔
- **بارکوڈ اسکینر**: کی بورڈ کی طرح کام کرتا ہے (USB اسکینر بس ٹائپ کر دیتا ہے)۔
- **نقد واپسی کا کیلکولیٹر** — گاہک جتنے دے، باقی خود نکل آتا ہے؛ فوری بٹن (100، 500، 1000…)۔
- **کارٹ ہولڈ** — درمیان میں بل روک کر دوسرا گاہک نمٹائیں۔
- **Round-off**: بل کو قریب ترین 10 روپے پر نیچے گول کرنا (Settings سے آن/آف) — **ساتھ cost guard**: گول کرنے کے بعد بھی بکری خرید قیمت سے نیچے نہیں جاتی۔
- **ادائیگی کے طریقے**: نقد، ادھار، آن لائن، کارڈ — اور **ملا کر (Split)** مثلاً آدھا نقد آدھا ادھار۔
- **Loyalty points** — کمانا اور خرچ کرنا (1 پوائنٹ = 1 روپیہ)، گاہک کے صفحے پر ستارے۔
- **چھوٹ (Discount)** — روپے میں یا فیصد میں، **رول کے حساب سے حد** (نیچے Settings دیکھیں)۔

### 2.2 Products — `/products`
- اپنی **Categories اور Sub-categories** (مثلاً `Medicines › Dard/Bukhar`) — 2 سطح تک۔
- **جہاں کہیں بھی کیٹیگری/کمپنی چنیں، وہیں نئی بنا سکتے ہیں** (فارم چھوڑنے کی ضرورت نہیں)۔
- **Filters ہر فہرست پر**: کیٹیگری، کمپنی، کمرہ، کم اسٹاک، ختم، expiry، اور 6 طرح کی ترتیب۔
- **Groups**: کیٹیگری / کمپنی / کمرے کے حساب سے گروپ — سر پر کلک کریں تو فولڈ ہو جاتا ہے۔
- **Product Detail** (`/products/[id]`): تصویر (فائل یا **کیمرا**)، ریٹس، بیچز اور expiry، بکری کے اعداد، ریٹ کی تاریخ، اور **مکمل stock ledger** (کب کیا آیا/گیا)۔
- **کمرہ / الماری / Rack** کا ریکارڈ۔
- **اپنی فیلڈز** (Custom fields) — جیسے Shelf، Salt، وغیرہ؛ ضروری یا اختیاری۔

### 2.3 Purchases (Stock-In) — `/purchases`
- بل `PINV-0001`، بیچ نمبر، expiry، قیمت۔
- **Free / Sample لائن** — مال اسٹاک میں آتا ہے مگر بل اور سپلائر کے کھاتے میں **نہیں** جڑتا (کمپنی کی مفت دوائی)۔
- سپلائر کا کھاتہ خودکار بڑھتا ہے۔

### 2.4 Stock — `/stock` اور `/stock-take`
- **Write-off / Adjust**: expiry، ٹوٹ پھوٹ، گم شدہ، گنتی کی درستی — نقصان کی قیمت **خرید ریٹ** پر (اصل نقصان)۔
- **گنتی (Stock-take)**:
  - سیشن کھولیں (`ST-0001`) → کتاب کا اسٹاک "فریز" ہو جاتا ہے۔
  - گنتی لکھیں → **کتاب / گنتی / فرق / قیمت** ساتھ ساتھ نظر آتے ہیں۔
  - "صرف فرق والی" سے چھانیں۔
  - **Apply** → بیچز درست، movement ریکارڈ، اور **کتاب کا منفی اسٹاک بھی ٹھیک ہو جاتا ہے**؛ ایسی دوا جو کتاب میں تھی ہی نہیں مگر گنتی میں ملی → `GINTI-ST-xxxx` بیچ خود بن جاتا ہے۔
  - ایک سیشن صرف ایک بار لاگو ہوتا ہے (دوبارہ نہیں)۔

### 2.5 Sales / Returns — `/sales`
- پچھلے بل تلاش کریں: **بل نمبر، گاہک، فون، یا دوا کا نام** سے۔
- **مکمل واپسی اور جزوی واپسی**۔
- **رش کے وقت کی واپسی** (`PR-xxxx`): بل نہ ہو تب بھی پیسے لوٹائیں — مال **قرنطینہ** میں رہتا ہے، ایک سرخ "pending" نشان چمکتا رہتا ہے؛ بعد میں اصل بل سے جوڑ دیں (اختیاری طور پر مال واپس اسٹاک میں)۔
- صرف owner/manager مال واپس اسٹاک میں ڈال سکتے ہیں (کیشیئر کی واپسی ہمیشہ قرنطینہ میں رہتی ہے)۔
- Filters: ادائیگی، حالت، نفع/نقصان، کم از کم رقم، تاریخ۔

### 2.6 Customers & Credit — `/customers`
- کھاتہ (ادھار)، ادھار کی **حد**، VIP/Doctor درجہ، نوٹس، تصویر (فائل یا **کیمرا**)۔
- **ادھار وصولی** — ادھار کم ہوتا ہے اور نقد گلّے میں جڑتا ہے۔
- **مکمل تاریخ**: ہر بل، ہر ادائیگی، ہر واپسی، اور فون سے تلاش۔
- **اپنی فیلڈز** (مثلاً CNIC)۔

### 2.7 Suppliers — `/suppliers`
- ہر سپلائر کا **پورا کھاتہ**: خریداری کے بل، ادائیگیاں، واپسیاں، ادائیگی کا بٹن، ان لائن ترمیم، اپنی فیلڈز۔
- **سپلائر کو مال واپسی** (`SR-0001`): expiry / خراب / غلط مال — اسٹاک نکلتا ہے اور جو دینا ہے وہ کم ہوتا ہے (یا کریڈٹ نوٹ بنتا ہے)۔
- واپسی **اسٹاک سے زیادہ نہیں ہو سکتی** (جلدی پکڑ لیتا ہے)۔

### 2.8 Cash & Day-end — `/cash`
- **گلّا (Shift)**: اوپننگ فلوٹ → بکری/وصولی/خرچے/ادائیگیاں → **زندہ "Expected cash"** → بند کرتے وقت گنی ہوئی رقم اور **فرق (کم/زیادہ)** محفوظ۔
- **Shift handover**: بند کرتے وقت بتائیں **کون سنبھالے گا** — گنی ہوئی رقم اگلے شفٹ کا اوپننگ فلوٹ بن جاتی ہے، "کِس نے → کِس کو" ریکارڈ، اور **ہینڈ اوور پرچی** (دونوں دستخط کے ساتھ، چھپنے کے قابل)۔
- اخراجات (خرچے) اور مالک کی نکاسی (drawings)۔
- شفٹ نہ کھلی ہو تو کاؤنٹر پر پیلا پیغام۔

### 2.9 Expiry & Stock alerts — `/alerts`
- **3 درجے** (اپنے دن اور رنگ Settings میں)۔
- **Reorder کی فہرست اب WhatsApp آرڈر پیڈ ہے**: دوائیں ٹک کریں، مقداریں لکھیں، سپلائر کا نمبر ڈالیں → WhatsApp کھل جاتا ہے جس میں آرڈر لکھا ہوا ہے۔
- "آج کا خلاصہ" بھی اسی طرح بھیج سکتے ہیں۔
- Expiry والے بیچ ٹک کر کے **سپلائر کو واپسی** میں بھیج سکتے ہیں (ایک کلک)۔
- فری/سیمپل اسٹاک کی الگ فہرست۔

### 2.10 Reports — `/reports`
- **آج / 7 دن / 30 دن / اس مہینے** (بٹن سے فوراً بدلتا ہے)۔
- کارڈز: بل، اشیاء، بکری، چھوٹ، **منافع + مارجن %**، اوسط بل، نقد، ادھار، واپسی، خرچے، خریداری۔
- روزانہ کی بار چارٹ، **ٹاپ-10 دوائیں**، **کیٹیگری کے حساب سے تقسیم**، **Dead stock** (60 دن سے نہ بکنے والی)۔
- CSV ڈاؤن لوڈ اور WhatsApp خلاصہ۔ صرف owner/manager (کیشیئر کو 307)۔

### 2.11 Data (Excel) — `/import`
- **نئی چیزیں لانا**: نمونہ فائل → خشک پیش نظارہ (dry-run) → درآمد۔ ڈپلیکیٹ خود چھوڑ دیتا ہے۔
- **موجودہ ریکارڈز کو فائل سے بدلنا (Bulk update)**: پورا ڈیٹا `.xlsx` میں ڈاؤن لوڈ کریں (دوائیں، گاہک، سپلائر، کیٹیگریز، کمپنیاں، بیچز، Settings — **تصویریں نہیں**)، جو مرضی بدلیں، واپس اپ لوڈ کریں → ہر لائن کا **پہلے → بعد** پیش نظارہ، پھر لاگو۔
  - **خالی سیل = کوئی تبدیلی نہیں** (غلطی سے کچھ نہیں مٹتا)؛ صاف کرنا ہو تو `__CLEAR__`۔
  - **کھاتے کا بیلنس اور اسٹاک کی مقدار فائل سے کبھی نہیں بدلتے**۔

### 2.12 Black box / Backup — `/audit`
- **ہر کام کا ریکارڈ**: کس نے، کب، کیا کیا — فلٹر (عمل، چیز، تاریخ، الفاظ)؛ **کبھی ڈیلیٹ نہیں ہوتا**۔
- **بیک اپ**: ایک ہی `.zip` جس میں **پورا ڈیٹا بیس + `data/photos/` کی ساری تصویریں**؛ "صرف ڈیٹا بیس" کا آپشن بھی۔
- **بحالی (Restore)**: `.zip` یا `.db` اپ لوڈ کریں — پرانی ڈیٹا بیس کی حفاظتی کاپی خود بنتی ہے، پھر ایپ **بغیر ری اسٹارٹ** نئی ڈیٹا بیس پر چلنے لگتی ہے۔
- **خودکار روزانہ بیک اپ**: `data/backups/` میں (Settings سے آن کریں؛ پرانے خود بخود کٹتے ہیں)۔

### 2.13 Cloud sync (Supabase) — `/sync`
- ڈیٹا کو کلاؤڈ پر بھیجیں (push) اور واپس لائیں (pull) — **مقامی ڈیٹا بیس ہمیشہ اصل رہتا ہے**۔
- نیا صفحہ: حالت، گنتی (دوائیں/گاہک/سپلائر/بکری/بیچز)، تین بٹن۔
- لاگو کرنے سے پہلے `area11-before-sync-*.db` خودکار بیک اپ۔
- مکمل سیٹ اپ: `docs/SUPABASE.md`۔

### 2.14 Settings — `/settings`
- 14 سے زیادہ حصے — **ہر حصہ کلک سے کھلتا ہے**۔
- وہیں سے **Custom fields** اور **Staff (PIN)** کا انتظام۔

### 2.15 دیگر
- **Roles**: owner (سب کچھ)، manager (تقریباً سب)، cashier (صرف کاؤنٹر، گاہک، واپسی) — اور **URL سطح پر روک** (چھپا ہوا لنک بھی نہیں کھلتا)۔
- **PWA / آف لائن**: انسٹال ہو سکتی ہے، انٹرنیٹ بند ہو تو پیلی پٹی اور آف لائن صفحہ۔
- **WhatsApp**: `wa.me` لنک (مفت، کوئی API key نہیں)؛ `03xx` نمبر خود `92…` بن جاتا ہے۔
- **Thermal receipt**: 58mm / 80mm، پرنٹ ویو (براؤزر پرنٹ) — پرنٹر ڈرائیور کی دکان پر جانچ باقی ہے۔

## 3. Settings کی **پوری فہرست** — ہر لائن کیا کرتی ہے

> نوٹ: جو لائنیں **⭐** سے نشان زد ہیں وہ روزمرہ کے کام میں سب سے زیادہ اثر رکھتی ہیں۔

### 3.1 Store & Branding
| Setting | کیا کرتی ہے | کہاں نظر آتی ہے |
|---|---|---|
| `store.name` | دکان کا نام | رسید، رپورٹ، WhatsApp پیغام |
| `store.address` / `store.phone` | پتہ اور فون | رسید کے سر/پاؤں میں |
| `store.footerNote` | رسید کے آخر میں جملہ | رسید |
| `store.terms` | شرائط (واپسی وغیرہ) | رسید |
| `brand.appName` / `brand.shortName` | ایپ کا نام اور چھوٹا نام | ٹائٹل، موبائل آئیکن |
| `brand.logoDataUrl` | لوگو کی تصویر | لاگ ان اور رسید |
| `brand.primaryColor` | بنیادی رنگ | پوری ایپ کا رنگ |

### 3.2 Billing & Numbering
| Setting | کیا کرتی ہے |
|---|---|
| `bill.salePrefix` ⭐ | بکری کے بل کا آغاز — `INV-` → `INV-0001` |
| `bill.purchasePrefix` ⭐ | خریداری کا بل — `PINV-` |
| `bill.numberPadding` | نمبر کتنے ہندسوں کا (4 → `0001`) |
| `bill.roundMode` ⭐ | `down10` = قریب ترین 10 روپے پر **نیچے**؛ `none` = بالکل گول نہ کریں |
| `bill.roundTo` | کس عدد پر گول کرنا ہے (10) |
| `bill.nextSaleNo` / `bill.nextPurchaseNo` | اگلا نمبر — **ایپ خود بڑھاتی ہے، ہاتھ سے مت بدلیں** |
| `bill.stockTakePrefix` | گنتی کا نمبر `ST-` (⚠️ فی الحال Settings صفحے پر **نظر نہیں آتا**) |
| `bill.provisionalPrefix` | رش والی واپسی `PR-` (⚠️ Settings پر نظر نہیں آتا) |
| `bill.supplierReturnPrefix` | سپلائر واپسی `SR-` (⚠️ Settings پر نظر نہیں آتا) |

### 3.3 Tax ⭐ (آپ کا سوال: "ٹیکس سسٹم Settings سے آن/آف ہوگا؟")
**ہاں — مکمل طور پر۔**
- `tax.enabled` → **آن/آف** (فی الحال **بند** ہے)۔
- `tax.percent` → کتنے فیصد (جو بھی لکھیں، مثلاً 1 یا 17)۔
- `tax.label` → رسید پر ٹیکس کا نام (مثلاً "Sales Tax")۔
- **اثر:** آن کرتے ہی ہر بل پر ٹیکس لگتا ہے، سب ٹوٹل کے بعد الگ لائن میں چھپتا ہے، اور رپورٹوں میں شامل ہوتا ہے۔
- **نہیں ہے:** الگ ٹیکس رپورٹ (ٹیکس ریٹرن کے لیے ماہانہ ٹیکس کا حساب) — یہ ایک خلا ہے، نیچے §5 میں۔

### 3.4 Discount ⭐
| Setting | کیا کرتی ہے |
|---|---|
| `discount.enabled` | چھوٹ بالکل آن/آف |
| `discount.mode` | **`margin`** = حد منافع پر لگے (آپ کا انتخاب) · **`retail`** = حد بکری ریٹ پر لگے |
| `discount.maxPercentCashier` | کیشیئر زیادہ سے زیادہ کتنی چھوٹ دے سکتا ہے (**5 %**) |
| `discount.maxPercentManager` | manager کی حد (**20 %**) · owner پر کوئی حد نہیں |
| `discount.blockBelowCost` | **خرید قیمت سے نیچے چھوٹ کسی کو نہیں** (spec 7.3) — ⚠️ Settings صفحے پر **نظر نہیں آتا** |

> یہ حدیں **سرور پر** لگتی ہیں — کوئی بھی UI چھوٹ کر ان سے آگے نہیں جا سکتا۔

### 3.5 Expiry & Reorder alerts
- `expiry.levels` — 3 درجے، ہر ایک کے **دن، رنگ اور نام** (مثلاً 365/180/90 دن)۔
- `reorder.enabled` — کم اسٹاک کی تنبیہ آن/آف۔
- `reorder.levels` — 3 درجے (warning ×2، critical ×1، out ×0) — یعنی ری آرڈر لیول کا کتنا گنا بچنے پر کیا کہنا ہے۔

### 3.6 Loyalty
| Setting | کیا کرتی ہے |
|---|---|
| `loyalty.enabled` | پوائنٹس آن/آف (**فی الحال بند**) |
| `loyalty.rupeesPerPoint` | کتنے روپے کی خریداری پر 1 پوائنٹ |
| `loyalty.vipThreshold` | کتنے پوائنٹ پر گاہک VIP |

## 6. ⚠️ وہ چیزیں جو **فائنل کرتے وقت مسئلہ بن سکتی ہیں**

> یہ حصہ سب سے اہم ہے — براہِ کرم ایک بار ضرور پڑھیں۔

### 6.1 سیکیورٹی / رسائی
1. **ڈیفالٹ مالک کا پاس ورڈ `area11` اور PIN `1111` ہے۔**
   → **لازمی بدلیں:** `node scripts/reset-login.mjs --owner "اپنا نیا پاس ورڈ"`
   (ورنہ کوئی بھی مالک کے طور پر اندر آ سکتا ہے)۔
2. **`sync.key` ڈیٹا بیس میں صاف (plain) محفوظ ہے** اور Settings صفحے پر پاس ورڈ باکس میں آتا ہے۔
   → اگر کوئی آپ کی ڈیٹا بیس کی فائل لے جائے تو key مل جائے گی۔ ڈیٹا بیس کی فائل **کبھی کسی کو نہ دیں** اور بیک اپ محفوظ جگہ رکھیں۔
3. **ایپ انٹرنیٹ پر براہِ راست مت لگائیں** (بغیر HTTPS اور بغیر مضبوط پاس ورڈ کے)۔ گھر سے دیکھنا ہو تو پہلے پاس ورڈ بدلیں اور HTTPS لگائیں۔
4. **لاگ ان کی کوششوں پر ہلکی سی روک ہے** (تھوڑی دیر کے لیے بلاک) — کئی کوششیں ناکام ہوں تو وہی IP کچھ دیر رک جاتی ہے۔ یہ میموری میں ہے، سرور بند ہو تو صاف ہو جاتی ہے۔

### 6.2 ڈیٹا / ڈیٹا بیس
5. **`data/` فولڈر کبھی ڈیلیٹ نہ کریں** — اصل ڈیٹا وہیں ہے۔
   (خوش قسمتی سے یہ Git میں محفوظ **نہیں** ہوتا، اس لیے کوڈ اور ڈیٹا الگ الگ رہتے ہیں۔)
6. **بیک اپ میں `data/photos/` شامل ہے** — پرانے طریقے کا صرف `.db` بیک اپ تصویریں نہیں بچاتا تھا؛ **نیازیپ (`.zip`) والا بیک اپ ضرور لیں**۔
7. **اگر ایپ کو اپ ڈیٹ کرنا ہو تو پہلے بیک اپ** (نیا کوڈ ڈیٹا بیس میں نئے کالم خود جوڑ لیتا ہے، مگر احتیاط بہتر)۔
8. **`applyPacket` (cloud سے ڈیٹا لانا) پوری ٹیبل بدل دیتا ہے** — اس لیے پہلے خودکار بیک اپ بنتا ہے۔ اسے سمجھے بغیر "لا کر لگائیں" مت دبائیں؛ یہ دکان کے ڈیٹا پر **اوپر سے لکھ دیتا ہے**۔

### 6.3 حساب / نمبر (فائنینسنگ سے پہلے)
9. **`bill.nextSaleNo` / `nextPurchaseNo` کو ہاتھ سے مت بدلیں** — بل نمبر ٹوٹ سکتے ہیں (ایک ہی نمبر دو بار)۔
10. **فائل سے Bulk update میں "کھاتے کا بیلنس" اور "اسٹاک کی مقدار" بدلے نہیں جا سکتے** — یہ جان بوجھ کر کیا گیا ہے (حساب خراب نہ ہو)۔ بدلنا ہو تو ادائیگی/واپسی یا گنتی (Stock-take) استعمال کریں۔
11. **منافع کا حساب "خرید قیمت" پر ہے** (جو بیچ کے ساتھ محفوظ ہوئی تھی)۔ اگر کوئی بیچ کی قیمت درج ہی نہ ہو تو منافع غلط دکھ سکتا ہے۔
12. **Round-off اب ہر بل پر آئٹمز میں بھی تقسیم ہوتا ہے** (پہلے صرف کل پر لگتا تھا جس سے ہر بل میں روپے کا فرق رہتا تھا) — اب ہر بل کا کل = آئٹمز کا جوڑ۔ یہ ٹھیک کر دیا گیا ہے اور اس پر ٹیسٹ بھی ہیں۔

### 6.4 چلانے کا ماحول
13. **Node.js ≥ 22.5 لازمی ہے** (اس سے پرانے ورژن پر `node:sqlite` نہیں چلتا)۔
14. **یہ ایپ Netlify / Vercel / GitHub Pages پر نہیں چل سکتی** — ڈیٹا بیس ایک فائل ہے جسے مستقل ڈسک چاہیے۔ دکان کا پی سی یا کوئی Node ہوسٹ (VPS) استعمال کریں۔
15. **Netlify والا پروجیکٹ صرف پرانے Vite ڈیمو کے لیے ہے** — اس کی Base directory `legacy-demo-vite` کر دیں۔
16. **کیمرا LAN پر کام نہیں کرتا** (بغیر HTTPS) — یہ براؤزر کی حد ہے، ایپ کی کمی نہیں۔

### 6.5 کوڈ / ریپو
