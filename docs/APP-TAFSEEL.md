## 1. ایپ کیسے چلتی ہے (ایک نظر میں)

- یہ ایک **Next.js + SQLite** ایپ ہے جو **دکان کے کمپیوٹر** پر چلتی ہے۔
- **انٹرنیٹ کے بغیر بھی پوری چلتی ہے** (سوائے کلاؤڈ سنک اور WhatsApp لنک کے)۔
- ڈیٹا ایک ہی فائل میں ہے: `data/area11.db` (تصویریں `data/photos/` فولڈر میں)۔
- **Node.js ≥ 22.5** درکار ہے (SQLite بلٹ اِن ہے) — کوئی اور ڈیٹا بیس انسٹال نہیں کرنا۔
- دکان کے دوسرے آلات (ٹیب/فون) اسی وائی فائی پر `http://<پی سی کا IP>:3000` کھول سکتے ہیں۔

**چلانے کا طریقہ**

```
npm install
npm run dev      # ٹیسٹ کے لیے (http://localhost:3000)
npm run build && npm start   # دکان میں استعمال کے لیے
```

## 2. بنے ہوئے فیچرز (صفحہ بہ صفحہ)

### 2.1 Counter / Billing — `/pos`
- Box / Strip / Tablet میں بیچنا — پیک کا فارمولا آپ خود رکھتے ہیں (1 بکس = کتنی پٹی، 1 پٹی = کتنی گولی)۔
- **FEFO**: جو بیچ جلدی ختم ہو رہا ہو وہ پہلے بکتا ہے (منہگی/خراب ہونے والی دوائی کا نقصان کم)۔
- **بارکوڈ اسکینر**: کی بورڈ کی طرح کام کرتا ہے (USB اسکینر بس ٹائپ کر دیتا ہے)۔
- **نقد واپسی کا کیلکولیٹر** — گاہک جتنے دے، باقی خود نکل آتا ہے؛ فوری بٹن (100، 500، 1000…)۔
- **کارٹ ہولڈ** — درمیان میں بل روک کر دوسرا گاہک نمٹائیں۔
- **Round-off**: بل کو قریب ترین 10 روپے پر نیچے گول کرنا (Settings سے آن/آف) — **ساتھ cost guard**: گول کرنے کے بعد بھی بکری خرید قیمت سے نیچے نہیں جاتی۔
- **ادائیگی کے طریقے**: نقد، ادھار، آن لائن، کارڈ — اور **ملا کر (Split)** مثلاً آدھا نقد آدھا ادھار۔
- **Loyalty points** — کمانا اور خرچ کرنا (1 پوائنٹ = 1 روپیہ)، گاہک کے صفحے پر ستارے۔
- **چھوٹ (Discount)** — روپے میں یا فیصد میں، **رول کے حساب سے حد** (نیچے Settings دیکھیں)۔

### 2.2 Products — `/products`
- اپنی **Categories اور Sub-categories** (مثلاً `Medicines › Dard/Bukhar`) — 2 سطح تک۔
- **جہاں کہیں بھی کیٹیگری/کمپنی چنیں، وہیں نئی بنا سکتے ہیں** (فارم چھوڑنے کی ضرورت نہیں)۔
- **Filters ہر فہرست پر**: کیٹیگری، کمپنی، کمرہ، کم اسٹاک، ختم، expiry، اور 6 طرح کی ترتیب۔
- **Groups**: کیٹیگری / کمپنی / کمرے کے حساب سے گروپ — سر پر کلک کریں تو فولڈ ہو جاتا ہے۔
- **Product Detail** (`/products/[id]`): تصویر (فائل یا **کیمرا**)، ریٹس، بیچز اور expiry، بکری کے اعداد، ریٹ کی تاریخ، اور **مکمل stock ledger** (کب کیا آیا/گیا)۔
- **کمرہ / الماری / Rack** کا ریکارڈ۔
- **اپنی فیلڈز** (Custom fields) — جیسے Shelf، Salt، وغیرہ؛ ضروری یا اختیاری۔

### 2.3 Purchases (Stock-In) — `/purchases`
- بل `PINV-0001`، بیچ نمبر، expiry، قیمت۔
- **Free / Sample لائن** — مال اسٹاک میں آتا ہے مگر بل اور سپلائر کے کھاتے میں **نہیں** جڑتا (کمپنی کی مفت دوائی)۔
- سپلائر کا کھاتہ خودکار بڑھتا ہے۔

### 2.4 Stock — `/stock` اور `/stock-take`
- **Write-off / Adjust**: expiry، ٹوٹ پھوٹ، گم شدہ، گنتی کی درستی — نقصان کی قیمت **خرید ریٹ** پر (اصل نقصان)۔
- **گنتی (Stock-take)**:
  - سیشن کھولیں (`ST-0001`) → کتاب کا اسٹاک "فریز" ہو جاتا ہے۔
  - گنتی لکھیں → **کتاب / گنتی / فرق / قیمت** ساتھ ساتھ نظر آتے ہیں۔
  - "صرف فرق والی" سے چھانیں۔
  - **Apply** → بیچز درست، movement ریکارڈ، اور **کتاب کا منفی اسٹاک بھی ٹھیک ہو جاتا ہے**؛ ایسی دوا جو کتاب میں تھی ہی نہیں مگر گنتی میں ملی → `GINTI-ST-xxxx` بیچ خود بن جاتا ہے۔
  - ایک سیشن صرف ایک بار لاگو ہوتا ہے (دوبارہ نہیں)۔

### 2.5 Sales / Returns — `/sales`
- پچھلے بل تلاش کریں: **بل نمبر، گاہک، فون، یا دوا کا نام** سے۔
- **مکمل واپسی اور جزوی واپسی**۔
- **رش کے وقت کی واپسی** (`PR-xxxx`): بل نہ ہو تب بھی پیسے لوٹائیں — مال **قرنطینہ** میں رہتا ہے، ایک سرخ "pending" نشان چمکتا رہتا ہے؛ بعد میں اصل بل سے جوڑ دیں (اختیاری طور پر مال واپس اسٹاک میں)۔
- صرف owner/manager مال واپس اسٹاک میں ڈال سکتے ہیں (کیشیئر کی واپسی ہمیشہ قرنطینہ میں رہتی ہے)۔
- Filters: ادائیگی، حالت، نفع/نقصان، کم از کم رقم، تاریخ۔

### 2.6 Customers & Credit — `/customers`
- کھاتہ (ادھار)، ادھار کی **حد**، VIP/Doctor درجہ، نوٹس، تصویر (فائل یا **کیمرا**)۔
- **ادھار وصولی** — ادھار کم ہوتا ہے اور نقد گلّے میں جڑتا ہے۔
- **مکمل تاریخ**: ہر بل، ہر ادائیگی، ہر واپسی، اور فون سے تلاش۔
- **اپنی فیلڈز** (مثلاً CNIC)۔

### 2.7 Suppliers — `/suppliers`
- ہر سپلائر کا **پورا کھاتہ**: خریداری کے بل، ادائیگیاں، واپسیاں، ادائیگی کا بٹن، ان لائن ترمیم، اپنی فیلڈز۔
- **سپلائر کو مال واپسی** (`SR-0001`): expiry / خراب / غلط مال — اسٹاک نکلتا ہے اور جو دینا ہے وہ کم ہوتا ہے (یا کریڈٹ نوٹ بنتا ہے)۔
- واپسی **اسٹاک سے زیادہ نہیں ہو سکتی** (جلدی پکڑ لیتا ہے)۔

### 2.8 Cash & Day-end — `/cash`
- **گلّا (Shift)**: اوپننگ فلوٹ → بکری/وصولی/خرچے/ادائیگیاں → **زندہ "Expected cash"** → بند کرتے وقت گنی ہوئی رقم اور **فرق (کم/زیادہ)** محفوظ۔
- **Shift handover**: بند کرتے وقت بتائیں **کون سنبھالے گا** — گنی ہوئی رقم اگلے شفٹ کا اوپننگ فلوٹ بن جاتی ہے، "کِس نے → کِس کو" ریکارڈ، اور **ہینڈ اوور پرچی** (دونوں دستخط کے ساتھ، چھپنے کے قابل)۔
- اخراجات (خرچے) اور مالک کی نکاسی (drawings)۔
- شفٹ نہ کھلی ہو تو کاؤنٹر پر پیلا پیغام۔

### 2.9 Expiry & Stock alerts — `/alerts`
- **3 درجے** (اپنے دن اور رنگ Settings میں)۔
- **Reorder کی فہرست اب WhatsApp آرڈر پیڈ ہے**: دوائیں ٹک کریں، مقداریں لکھیں، سپلائر کا نمبر ڈالیں → WhatsApp کھل جاتا ہے جس میں آرڈر لکھا ہوا ہے۔
- "آج کا خلاصہ" بھی اسی طرح بھیج سکتے ہیں۔
- Expiry والے بیچ ٹک کر کے **سپلائر کو واپسی** میں بھیج سکتے ہیں (ایک کلک)۔
- فری/سیمپل اسٹاک کی الگ فہرست۔

### 2.10 Reports — `/reports`
- **آج / 7 دن / 30 دن / اس مہینے** (بٹن سے فوراً بدلتا ہے)۔
- کارڈز: بل، اشیاء، بکری، چھوٹ، **منافع + مارجن %**، اوسط بل، نقد، ادھار، واپسی، خرچے، خریداری۔
- روزانہ کی بار چارٹ، **ٹاپ-10 دوائیں**، **کیٹیگری کے حساب سے تقسیم**، **Dead stock** (60 دن سے نہ بکنے والی)۔
- CSV ڈاؤن لوڈ اور WhatsApp خلاصہ۔ صرف owner/manager (کیشیئر کو 307)۔

### 2.11 Data (Excel) — `/import`
- **نئی چیزیں لانا**: نمونہ فائل → خشک پیش نظارہ (dry-run) → درآمد۔ ڈپلیکیٹ خود چھوڑ دیتا ہے۔
- **موجودہ ریکارڈز کو فائل سے بدلنا (Bulk update)**: پورا ڈیٹا `.xlsx` میں ڈاؤن لوڈ کریں (دوائیں، گاہک، سپلائر، کیٹیگریز، کمپنیاں، بیچز، Settings — **تصویریں نہیں**)، جو مرضی بدلیں، واپس اپ لوڈ کریں → ہر لائن کا **پہلے → بعد** پیش نظارہ، پھر لاگو۔
  - **خالی سیل = کوئی تبدیلی نہیں** (غلطی سے کچھ نہیں مٹتا)؛ صاف کرنا ہو تو `__CLEAR__`۔
  - **کھاتے کا بیلنس اور اسٹاک کی مقدار فائل سے کبھی نہیں بدلتے**۔

### 2.12 Black box / Backup — `/audit`
- **ہر کام کا ریکارڈ**: کس نے، کب، کیا کیا — فلٹر (عمل، چیز، تاریخ، الفاظ)؛ **کبھی ڈیلیٹ نہیں ہوتا**۔
- **بیک اپ**: ایک ہی `.zip` جس میں **پورا ڈیٹا بیس + `data/photos/` کی ساری تصویریں**؛ "صرف ڈیٹا بیس" کا آپشن بھی۔
- **بحالی (Restore)**: `.zip` یا `.db` اپ لوڈ کریں — پرانی ڈیٹا بیس کی حفاظتی کاپی خود بنتی ہے، پھر ایپ **بغیر ری اسٹارٹ** نئی ڈیٹا بیس پر چلنے لگتی ہے۔
- **خودکار روزانہ بیک اپ**: `data/backups/` میں (Settings سے آن کریں؛ پرانے خود بخود کٹتے ہیں)۔

### 2.13 Cloud sync (Supabase) — `/sync`
- ڈیٹا کو کلاؤڈ پر بھیجیں (push) اور واپس لائیں (pull) — **مقامی ڈیٹا بیس ہمیشہ اصل رہتا ہے**۔
- نیا صفحہ: حالت، گنتی (دوائیں/گاہک/سپلائر/بکری/بیچز)، تین بٹن۔
- لاگو کرنے سے پہلے `area11-before-sync-*.db` خودکار بیک اپ۔
- مکمل سیٹ اپ: `docs/SUPABASE.md`۔

### 2.14 Settings — `/settings`
- 14 سے زیادہ حصے — **ہر حصہ کلک سے کھلتا ہے**۔
- وہیں سے **Custom fields** اور **Staff (PIN)** کا انتظام۔

### 2.15 دیگر
- **Roles**: owner (سب کچھ)، manager (تقریباً سب)، cashier (صرف کاؤنٹر، گاہک، واپسی) — اور **URL سطح پر روک** (چھپا ہوا لنک بھی نہیں کھلتا)۔
- **PWA / آف لائن**: انسٹال ہو سکتی ہے، انٹرنیٹ بند ہو تو پیلی پٹی اور آف لائن صفحہ۔
- **WhatsApp**: `wa.me` لنک (مفت، کوئی API key نہیں)؛ `03xx` نمبر خود `92…` بن جاتا ہے۔
- **Thermal receipt**: 58mm / 80mm، پرنٹ ویو (براؤزر پرنٹ) — پرنٹر ڈرائیور کی دکان پر جانچ باقی ہے۔

## 3. Settings کی **پوری فہرست** — ہر لائن کیا کرتی ہے

> نوٹ: جو لائنیں **⭐** سے نشان زد ہیں وہ روزمرہ کے کام میں سب سے زیادہ اثر رکھتی ہیں۔

### 3.1 Store & Branding
| Setting | کیا کرتی ہے | کہاں نظر آتی ہے |
|---|---|---|
| `store.name` | دکان کا نام | رسید، رپورٹ، WhatsApp پیغام |
| `store.address` / `store.phone` | پتہ اور فون | رسید کے سر/پاؤں میں |
| `store.footerNote` | رسید کے آخر میں جملہ | رسید |
| `store.terms` | شرائط (واپسی وغیرہ) | رسید |
| `brand.appName` / `brand.shortName` | ایپ کا نام اور چھوٹا نام | ٹائٹل، موبائل آئیکن |
| `brand.logoDataUrl` | لوگو کی تصویر | لاگ ان اور رسید |
| `brand.primaryColor` | بنیادی رنگ | پوری ایپ کا رنگ |

### 3.2 Billing & Numbering
| Setting | کیا کرتی ہے |
|---|---|
| `bill.salePrefix` ⭐ | بکری کے بل کا آغاز — `INV-` → `INV-0001` |
| `bill.purchasePrefix` ⭐ | خریداری کا بل — `PINV-` |
| `bill.numberPadding` | نمبر کتنے ہندسوں کا (4 → `0001`) |
| `bill.roundMode` ⭐ | `down10` = قریب ترین 10 روپے پر **نیچے**؛ `none` = بالکل گول نہ کریں |
| `bill.roundTo` | کس عدد پر گول کرنا ہے (10) |
| `bill.nextSaleNo` / `bill.nextPurchaseNo` | اگلا نمبر — **ایپ خود بڑھاتی ہے، ہاتھ سے مت بدلیں** |
| `bill.stockTakePrefix` | گنتی کا نمبر `ST-` (⚠️ فی الحال Settings صفحے پر **نظر نہیں آتا**) |
| `bill.provisionalPrefix` | رش والی واپسی `PR-` (⚠️ Settings پر نظر نہیں آتا) |
| `bill.supplierReturnPrefix` | سپلائر واپسی `SR-` (⚠️ Settings پر نظر نہیں آتا) |

### 3.3 Tax ⭐ (آپ کا سوال: "ٹیکس سسٹم Settings سے آن/آف ہوگا؟")
**ہاں — مکمل طور پر۔**
- `tax.enabled` → **آن/آف** (فی الحال **بند** ہے)۔
- `tax.percent` → کتنے فیصد (جو بھی لکھیں، مثلاً 1 یا 17)۔
- `tax.label` → رسید پر ٹیکس کا نام (مثلاً "Sales Tax")۔
- **اثر:** آن کرتے ہی ہر بل پر ٹیکس لگتا ہے، سب ٹوٹل کے بعد الگ لائن میں چھپتا ہے، اور رپورٹوں میں شامل ہوتا ہے۔
- **نہیں ہے:** الگ ٹیکس رپورٹ (ٹیکس ریٹرن کے لیے ماہانہ ٹیکس کا حساب) — یہ ایک خلا ہے، نیچے §5 میں۔

### 3.4 Discount ⭐
| Setting | کیا کرتی ہے |
|---|---|
| `discount.enabled` | چھوٹ بالکل آن/آف |
| `discount.mode` | **`margin`** = حد منافع پر لگے (آپ کا انتخاب) · **`retail`** = حد بکری ریٹ پر لگے |
| `discount.maxPercentCashier` | کیشیئر زیادہ سے زیادہ کتنی چھوٹ دے سکتا ہے (**5 %**) |
| `discount.maxPercentManager` | manager کی حد (**20 %**) · owner پر کوئی حد نہیں |
| `discount.blockBelowCost` | **خرید قیمت سے نیچے چھوٹ کسی کو نہیں** (spec 7.3) — ⚠️ Settings صفحے پر **نظر نہیں آتا** |

> یہ حدیں **سرور پر** لگتی ہیں — کوئی بھی UI چھوٹ کر ان سے آگے نہیں جا سکتا۔

### 3.5 Expiry & Reorder alerts

5. **`data/` فولڈر کبھی ڈیلیٹ نہ کریں** — اصل ڈیٹا وہیں ہے۔

9b. **منفی اسٹاک اصل نقصان چھپا سکتا ہے** — اسٹاک مائنس میں جانا عام بات ہے (گنتی کی غلطی، رائیڈر کا مال)، مگر اگر کوئی دوا **ہمیشہ** مائنس میں رہے تو سمجھیں کہ کہیں چوری، ٹوٹ پھوٹ یا اندراج کی غلطی ہو رہی ہے۔ مہینے میں ایک بار `/alerts` کا «Stock MINUS» والا کارڈ ضرور دیکھیں اور گنتی (Stock-take) لگائیں۔

## 9. Spec 1 — منفی (Negative) انوینٹری

**کیا بنایا گیا ہے**

- ✅ **بکری کبھی نہیں رکتی** — اسٹاک 0 یا کم ہو تب بھی بل بن جاتا ہے۔
- ✅ **اسکرین کے بالکل اوپر بڑا سرخ الرٹ** (sticky):
  «*Stock MINUS me ja raha hai — 2 cheezein*» اور نیچے ہر دوا کا حساب:
  «Test Dawa: maujood 5 · bill me 12 · **bad men −7**»۔
- ✅ کارٹ کی ہر لائن پر سرخ نشان: «⚠ stock minus me jayega (−7)»۔
- ✅ بل بچنے کے بعد بھی اوپر الرٹ بار میں پیغام رہتا ہے۔
- ✅ **ہر صفحے کے بالکل اوپر عالمی سرخ الرٹ** (AppShell) — ڈیش بورڈ، POS، پروڈکٹس، سیلز، رپورٹس، غرض **ہر جگہ**:
  «⚠ **Stock MINUS me hai — 3 dawa (en)** · (sab se zyada −9) · ginti ya purchase se theek karein · **Abhi dekhein**».
  صرف اسی سیشن کے لیے چھپایا جا سکتا ہے (دوبارہ لاگ اِن پر پھر نظر آئے گا)۔
- ✅ `/alerts` صفحے پر سب سے اوپر «**Stock MINUS me hai**» والا کارڈ (کتنی دوائیں، کتنا مائنس)۔
- ✅ `/stock` پر اسٹاک کم کرتے وقت وارننگ اب **بڑے سرخ الرٹ** میں (چھوٹی لائن میں چھپ کر نہیں)۔
- ✅ ہر منفی بکری بلیک باکس میں **`negative_sale`** کے نام سے محفوظ۔
- ✅ اسٹاک **واقعی** کم ہوتا ہے — اگر کوئی بھی بیچ خالی نہ ہو تو آخری بیچ سے کاٹا جاتا ہے (کتاب اور اصلیت میں فرق نہیں پڑتا)۔
- ✅ Settings سے بند کیا جا سکتا ہے: تب پیغام آئے گا «اتنا مال نہیں — Settings › Stock سے اجازت دیں» اور بکری رک جائے گی۔

**لائیو ثبوت (6 اکتوبر 2026)**
```
stock 5 tha · 12 beche → {"ok":true,"code":"INV-0001",
  "warnings":["…stock MINUS (-7) me chala gaya."],
  "negativeItems":[{"name":"Test Neg Dawa","inStockBase":5,"soldBase":12,"afterBase":-7}]}
setting OFF ki → 3 aur bechne par: HTTP 400 «stock me sirf -7 hain… (Manfi stock band hai)»
setting wapas ON → bikri ho gayi, ab stock −10
```

## 12b. واپسی کا مال **فوراً اسٹاک میں** — قرنطینہ ختم (مالک کا حکم 6-Oct-2026)

آپ نے واضح فرمایا: **"جیسے ہی پیسے نکلیں گے… اسی طرح اسٹاک ایڈ ہو جائے گا"**، اور یہ کہ
خراب / تاریخ گزشتہ مال آپ واپس لیتے ہی نہیں — لہٰذا قرنطینہ کی ضرورت نہیں۔

| پہلے (stage-37) | اب (stage-38) |
|---|---|
| واپسی پر مال «قرنطینہ» میں جاتا تھا، اسٹاک میں نہیں | واپسی کے **لمحے ہی** مال اسٹاک میں شامل (`restock = 1`) |
| «شیلف پر ڈالیں» دبانا پڑتا تھا | کچھ دبانے کی ضرورت نہیں — خودکار |
| قرنطینہ کارڈ بھرا رہتا تھا | کارڈ صرف **نادر صورت** کے لیے (جب کوئی جان بوجھ کر «اسٹاک میں واپس نہیں» چنے) |

- `/alerts` پر وہ کارڈ اب **«واپسی کا مال جو اسٹاک میں واپس نہیں ڈالا گیا»** کے نام سے ہے۔
- **لائیو ثبوت:** بل کے ساتھ 2 عدد واپسی → بیچ `-10 → -8` **اسی لمحے**؛ `sale_returns.restock = 1`۔

## 12c. الرٹس — **صرف مالک** وجہ لکھ کر ختم کرے (U-31) ⭐

آپ کا حکم: *"جس کو مالک بعد میں خود ختم کر سکتا ہے ریزن لکھ کے"*۔

- ہر الرٹ **ہر صفحے کے بالکل اوپر** نظر آتا ہے (آپ کہیں بھی ہوں)۔
- اسے **صرف مالک (owner)** ختم کر سکتا ہے — مینیجر / کیشیئر نہیں۔
  (کیشیئر کو صرف یہ جملہ نظر آتا ہے: «صرف مالک وجہ لکھ کر اس الرٹ کو ختم کر سکتے ہیں»)
- **وجہ لکھنا لازمی ہے** (کم از کم 3 حرف) — بغیر وجہ کے الرٹ ختم ہی نہیں ہوتا۔
- وجہ **مستقل محفوظ** ہو جاتی ہے (نئی ٹیبل `alert_dismissals`: وجہ، تاریخ/وقت، کس نے لکھی)۔
- وجہ **بلیک باکس** میں بھی درج ہوتی ہے (پرانا → نیا):
  `status: active → dismissed`, `reason: null → "…"`۔
- مالک چاہے تو `/alerts` پر **«واپس لائیں»** سے کسی بھی الرٹ کو دوبارہ زندہ کر سکتا ہے (یہ بھی لاگ ہوتا ہے)۔
- `/alerts` پر نیا کارڈ: **«الرٹس — جو مالک نے وجہ لکھ کر ختم کیے»** (وجہ + وقت + نام)۔

> نوٹ: یہ اب **صرف اسی نشست (session) تک محدود نہیں** — پہلے «✕» دبانے سے الرٹ چھپ جاتا تھا اور
> دوبارہ داخل ہوتے ہی واپس آ جاتا تھا۔ اب وجہ لکھنے کے بعد وہ ہمیشہ کے لیے ختم ہو جاتا ہے۔

**لائیو ثبوت:** منفی اسٹاک والی دوا کا الرٹ → بغیر وجہ کے «منظور نہیں»؛ وجہ لکھنے کے بعد الرٹ غائب،
وجہ `/alerts` اور بلیک باکس دونوں میں محفوظ۔ کیشیئر سے کوشش کروائی گئی
→ **«الرٹ ختم کرنا صرف مالک کا کام ہے»**۔

## 12d. منفی اسٹاک **کہیں بھی کام نہیں روکتا** (U-30) ⭐

آپ کا حکم: *"اگر کہیں بھی منفی اسٹاک یا کوئی بھی ایسا کام ہوتا ہے اس کو صرف الرٹ جانا چاہیے"*۔

| جگہ | پہلے | اب |
|---|---|---|
| سپلائر واپسی (اسٹاک سے زیادہ مقدار) | **خرابی** — «Batch me sirf N hain…» کام رک جاتا تھا | کام **ہو جاتا ہے** + الرٹ: «stock MINUS me gaya» |
| اسٹاک ایڈجسٹ / رائٹ آف (write-off) | رک جاتا تھا | **الرٹ** کے ساتھ درج |
| بکری (POS) | (پہلے ہی) جاری | جاری + الرٹ |

- جو **الرٹ** جاتا ہے وہ تب تک رہتا ہے جب تک مالک وجہ لکھ کر ختم نہ کرے (§12c)۔
- **لائیو ثبوت:** بیچ میں `-4` تھے، سپلائر کو 6 واپس بھیجے → **کام مکمل**، اسٹاک `-10`،
  اور جواب میں `warnings: ["…stock MINUS (-10) me gaya"]`۔

## 12e. بغیر بل (جلدی) واپسی — اسٹاک فوراً + الرٹ قائم (U-33) ⭐

آپ کا حکم: *"ایک دفعہ مال فوری طور پر اسٹاک میں ایڈ ہو جائے گا… الرٹ جاتا رہے گا جب تک یا خود
اونر وجہ لکھ کے ختم نہیں کر رہا تب تک شو ہوتا رہے گا"*۔

1. واپسی درج ہوتے ہی **مال اسٹاک میں شامل** ہو جاتا ہے (پہلے «قرنطینہ» میں رکا رہتا تھا)۔
2. بل **بعد میں جوڑنے کی اجازت** بدستور موجود۔
3. **لیکن بل جڑ جانے کے بعد بھی الرٹ ختم نہیں ہوتا** — وہ تب تک دکھتا رہتا ہے جب تک مالک
   وجہ لکھ کر ختم نہ کرے (الرٹ کا رنگ بدل کر پیلا/امبر ہو جاتا ہے:
   «بل (INV-…) جڑ گیا، مالک کی تصدیق باقی»)۔
4. بل جوڑتے وقت مال **دوبارہ** اسٹاک میں **نہیں** جاتا (دوہرا اضافہ نہ ہو)۔

**لائیو ثبوت:** `-7` پر 3 عدد واپسی → **اسی لمحے** `-4`؛ پھر بل جوڑا → اسٹاک `-4` **ہی رہا**
(دوہرا اضافہ نہیں ہوا) اور الرٹ بدستور موجود
(«PR-0001 — بل (INV-0001) جڑ گیا، مالک کی تصدیق باقی»)۔

## 12f. واپسی کی رسید (Return Receipt) — ہر واپسی کا **پکّا نمبر** (U-35) ⭐

آپ کا حکم: *"ہر سامان کا ایک اپنا مخصوص نمبر ہو جو تبدیل نہیں ہو سکتا، اور جب ہم تاریخ دیکھیں
تو سارا سامان نظر آئے کہ کون سا سامان کہاں گیا"*۔

- **ہر واپسی کو ایک مستقل نمبر ملتا ہے: `RET-0001`, `RET-0002` …** (نئی مائیگریشن `012_return_number`)
  - ایک ہی واپسی میں جتنی بھی دوائیں ہوں — سب پر **ایک ہی نمبر** (یعنی ایک واپسی = ایک رسید)۔
  - یہ نمبر **کبھی تبدیل نہیں ہوتا** اور بلیک باکس (`audit`) میں بھی درج ہوتا ہے۔
  - آغاز (prefix) اور نمبر Settings سے بدلے جا سکتے ہیں (`bill.returnPrefix`)۔
- **چھپنے والی رسید:** واپسی کے فوراً بعد ایک نئی کھڑکی میں رسید خود بخود کھل جاتی ہے (پرنٹ کے لیے تیار)۔
  - `/sales` پر ہر بل کے اندر **«واپسی کی رسیدیں»** — وہاں سے کسی بھی پرانی واپسی کی رسید دوبارہ چھاپ سکتے ہیں۔
  - **بغیر بل (جلدی) واپسی** کی بھی الگ رسید (`PR-0001`…) — `/sales` کے Provisional کارڈ پر «Raseed» بٹن۔
- رسید پر کیا ہوتا ہے: دکان کا نام/پتہ · **واپسی کا نمبر** · تاریخ/وقت · **اصل بل نمبر** · گاہک (نام/فون) ·
  دوائیں + مقدار + واپس رقم · **ہر آئٹم کے ساتھ «اسٹاک میں واپس» یا «قرنطینہ میں»** (یعنی سامان کہاں گیا) ·
  وجہ · **کل ریفنڈ** · وصول کنندہ اور دستخط کی لائن۔
- **لائیو ثبوت:** واپسی → `code: "RET-0001"`، DB میں `sale_returns.code = RET-0001`؛
  دوسری واپسی → خودبخود `RET-0002`؛ رسید کا صفحہ `/receipt/1?type=return&code=RET-0001` اور
  بغیر بل والی `/receipt/1?type=provisional` دونوں ٹھیک چھپ رہے ہیں۔

## 12g. نظرِ ثانی (Review) میں ملا ہوا **بڑا حسابی نقص** — واپسی کی لاگت ⭐

جائزے کے دوران پکڑا گیا: **واپسی پر مال شیلف پر واپس آ جاتا ہے، مگر رپورٹ اور کیش/ڈے اینڈ
اس کی لاگت (cost) منافع میں واپس نہیں شامل کرتے تھے** — یعنی منافع **کم** دکھایا جاتا تھا۔

**مثال (لائیو):** 6 عدد بکے (Rs 480)، لاگت Rs 300، پھر 3 عدد واپس آئے (Rs 240 واپس، لاگت Rs 150 شیلف پر)

| | پہلے | اب (درست) |
|---|---|---|
| منافع | **Rs −60** ❌ | **Rs 90** ✅ |
| حساب | `(480−240) − 300` | `(480−240) − (300−150)` |

- یہ نقص **تین جگہ** تھا: `/reports` کے کل (totals)، روزانہ کے چارٹ، «سب سے زیادہ بکنے والی دوائیں»،
  کیٹیگری کی تقسیم — اور **کیش / ڈے اینڈ** کے منافع میں۔
- نیا اصول (نئی فائل `src/lib/report-math.ts`): **واپسی کی لاگت تب ہی واپس ملے گی جب مال واقعی
  اسٹاک میں آیا ہو (`restock = 1`)**؛ اگر مال قرنطینہ میں ہے یا خراب ہو گیا تو لاگت واپس نہیں آتی (نقصان مانا جاتا ہے)۔
- اس اصول پر **5 نئے ٹیسٹ** ہیں (کل 51) تاکہ آئندہ یہ غلطی دوبارہ نہ ہو۔
- **لائیو ثبوت:** ایک ہی دن: بکری Rs 480 · واپسی Rs 240 · لاگت Rs 300 · **واپس آئی لاگت Rs 150**
  → **منافع Rs 90، مارجن 37.5%**؛ واپس آنے والے عدد **3**؛ کیش/ڈے اینڈ کا منافع بھی **Rs 90**۔

## 12h. قرنطینہ — **ہر سامان کا مستقل نمبر** اور پورا پتہ کہ «کون سا سامان کہاں گیا» (U-34) ⭐

آپ کا حکم: *"ہر سامان جو قرنطینہ میں ہوگا اس کا ایک اپنا مخصوص نمبر ہوگا جو تبدیل نہیں ہو سکتا،
اور جب ہم ہسٹری دیکھیں گے تو سارے سامان شو ہوگا کہ کون سا سامان کدھر گیا ہے"*۔

| | کیا ہوتا ہے |
|---|---|
| **مستقل نمبر** | قرنطینہ میں جانے والے ہر آئٹم کو **`Q-0001`, `Q-0002` …** ملتا ہے — **کبھی نہیں بدلتا** (نئی مائیگریشن `013_quarantine_tracking`) |
| **انجام (کہاں گیا)** | `disposition` فیلڈ: **قرنطینہ میں** → **اسٹاک میں واپس** / **ایکسپائری-خراب** / **فروخت** |
| **تاریخ + نوٹ + کس نے** | ہر فیصلے کے ساتھ وقت، نوٹ اور صارف محفوظ |
| **الرٹ** | جب تک مال قرنطینہ میں ہے **الرٹ جاتا رہتا ہے**؛ مالک وجہ لکھ کر بھی ختم کر سکتے ہیں (§12c) |
| **رسید** | واپسی کی رسید پر بھی قرنطینہ کا نمبر چھپتا ہے |

- `/alerts` پر اب **دو کارڈ**: (1) «ابھی قرنطینہ میں» — ہر آئٹم کے ساتھ **اسٹاک میں / خراب / فروخت** کے بٹن،
  (2) **«قرنطینہ کی پوری تاریخ — کون سا سامان کہاں گیا»** (نمبر، دوا، مقدار، انجام، نوٹ)۔
- مالک چاہیں تو قرنطینہ کا مال **بیچ بھی سکتے ہیں** (`sold`) — اور **خراب/ایکسپائری** میں بھیج سکتے ہیں (`expired` = write-off)۔
  صرف **«اسٹاک میں واپس»** سے اسٹاک بڑھتا ہے۔
- **عام واپسی (restock) اب بھی فوراً اسٹاک میں جاتی ہے** (U-32) — تب کوئی Q-نمبر نہیں بنتا۔
- **لائیو ثبوت:** `restock:false` واپسی → `Q-0001` + «قرنطینہ میں» + الرٹ؛ فیصلہ «خراب» →
  انجام «ایکسپائری/خراب»، الرٹ ختم؛ دوسری واپسی → `Q-0002` → «اسٹاک میں واپس» →
  بیچ `4 → 5`؛ تاریخ میں دونوں نمبر اپنے انجام کے ساتھ درج؛ رسید پر `Q-0001` چھپا؛
  عام واپسی (`RET-0003`) پر کوئی Q-نمبر نہیں — سیدھا اسٹاک۔
