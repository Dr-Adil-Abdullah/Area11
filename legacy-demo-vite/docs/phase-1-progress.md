## 2. ڈیٹا اور حساب کی حفاظتی جانچ

- تمام رقم **integer paisa** میں؛ پیک کی قیمت یا خرید مقدار میں binary floating-point rounding استعمال نہیں ہوتی۔
- بیچ کی دستیاب مقدار کارٹ کی تمام متعلقہ پیک سائز لائنز کو ملا کر چیک ہوتی ہے۔
- فروخت پر صرف منتخب بیچ سے بنیادی اکائیاں کم ہوتی ہیں۔
- ایکسپائر بیچ منتخب نہیں ہو سکتا؛ ہولڈ کارٹ کی ایکسپائری اور اسٹاک checkout پر دوبارہ چیک ہوتے ہیں۔
- ہولڈ کارٹ اسٹاک ریزرو نہیں کرتا، اور بحال کرنے سے موجودہ نامکمل کارٹ خاموشی سے ضائع نہیں ہوتا۔
- نقد رقم بل سے کم ہو تو فروخت مکمل نہیں ہوتی۔
- بل کی اصل رقم ہی خرید لاگت سے نیچے ہو تو راؤنڈنگ چھوڑنے کے بجائے فروخت بلاک ہوتی ہے۔
- انوائس اور اسٹاک ایک validated browser snapshot میں محفوظ ہوتے ہیں۔ لکھنے میں ناکامی پر دونوں میں تبدیلی نہیں ہوتی۔ یہ server database یا multi-counter transaction کی ضمانت نہیں۔
- خراب محفوظ ڈیٹا خودکار reset نہیں ہوتا؛ واضح Owner تصدیق درکار ہے۔

## 3. چلائے گئے checks

| Check                  | مقامی نتیجہ                                                  |
| ---------------------- | ------------------------------------------------------------ |
| `npm run typecheck`    | پاس                                                          |
| `npm test`             | 35 domain/repository tests پاس                               |
| `npm run test:e2e`     | 10 براؤزر ٹیسٹ پاس                                           |
| `npm run build`        | production assets کی build پاس؛ یہ production readiness نہیں |
| `npm run format:check` | پاس                                                          |
| `npm audit`            | جانچ کے وقت 0 معلوم dependency vulnerabilities               |

براؤزر ٹیسٹ میں desktop، 390px موبائل لے آؤٹ، پرنٹ CSS، PDF اور counter/stock/billing screens کے خودکار accessibility checks شامل ہیں۔ یہ حقیقی Android ڈیوائس، assistive technology یا ہارڈویئر کی دستی آزمائش کا بدل نہیں۔

اس sandbox میں Playwright کا عام browser CDN دستیاب نہیں تھا، اس لیے وہی براؤزر ٹیسٹ npm سے حاصل کردہ Chromium 153 executable کے ساتھ چلائے گئے۔ browser downloads اور generated artifacts Git کا حصہ نہیں۔ عمومی ماحول میں README کے مطابق Playwright کا browser installer استعمال کیا جا سکتا ہے۔

CI workflow شامل ہے، مگر اس کے GitHub پر چلنے کی تصدیق ابھی نہیں کی گئی؛ اوپر کے نتائج مقامی جانچ کے ہیں۔

## 4. اس ڈیمو کی واضح حدود

- تمام ابتدائی مصنوعات، سپلائر ڈلیوریز اور قیمتیں **نمونہ ڈیٹا** ہیں۔ کوئی فرضی سیلز نتیجہ کامیابی دکھانے کے لیے پہلے سے شامل نہیں کیا گیا۔
- ڈیٹا اسی براؤزر کے `localStorage` میں ہے؛ site data صاف ہونے پر ختم ہو سکتا ہے۔
- ایک وقت میں ایک فعال demo tab استعمال کریں۔ دوسرے tab کی تازہ تبدیلی کا detection بہترین کوشش ہے، production concurrency guarantee نہیں۔
- ٹیسٹنگ رول سوئچر حقیقی authentication یا server-side authorization نہیں ہے۔
- مکمل آف لائن startup، service worker، کلاؤڈ/ملٹی ڈیوائس سنک، بیک اپ اور immutable audit ابھی موجود نہیں۔
- ریٹرن، کیش کلوزنگ، مالک/سپلائر/کسٹمر کے کھاتے، advanced discount/tax، loyalty اور split payment ابھی نافذ نہیں کیے گئے۔
- پروڈکٹ کی category فہرست ابتدائی fixed فہرست ہے؛ custom category/field builder فیز 4 میں آئے گا۔
- اصل دکان کا نام اور رابطے صارف نے نہیں دیے؛ receipt header عارضی اور قابلِ تبدیلی ہے۔
- quantities مکمل configured base units ہیں؛ expiry مکمل تاریخ ہے، month-only تاریخ کو خودکار معنی نہیں دیے گئے۔ expiry والے دن فروخت ممکن ہے، اگلے دن بلاک ہوگی۔

## 5. ترتیب میں اگلا مرحلہ — فیز 2

فیز 1 کی بنیاد کے بعد اصل روڈ میپ کے مطابق:

1. اصل انوائس اور اسی بیچ سے منسلک سیلز ریٹرن؛ واپس مقدار اصل فروخت/پچھلے ریٹرنز سے زیادہ نہ ہو۔
2. گم شدہ بل کی تلاش، عارضی ریٹرن اور اصل بل سے تعلق مکمل ہونے تک مستقل pending alert۔
3. صبح کا float، شفٹ handover اور cash reconciliation۔
4. مالک کا drawing ledger، نقد/دوا کا استعمال اور رقم کی واپسی۔
5. روزمرہ اور ماہانہ دکان کے اخراجات۔
6. مکمل discount safeguards، خرید لاگت کا لاک اور متعلقہ اختیارات۔
